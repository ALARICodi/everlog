# everlog · 版本2(带账号)

> 这是**版本2**。和[版本1](https://github.com/ALARICodi/everlog/tree/v1)完全一样,
> 只多了一个账号系统:注册 / 登录 / 我的文章。
> 发布链路、格式、证明、验证器**一个字节都没改** —— 两个版本产出的证明完全通用。
>
> **账号不参与任何证明。** 它只解决一件事:换台设备还能找回自己发过什么。
> 已发布的文章不需要账号、不需要这个网站,任何人都能独立验证。

## 账号

- 用户号由系统随机分配、**不可更改**:`U` + 8 位数字,**不含 0**
  (不含 0 是为了不和字母 O 混淆 —— 这个号要被人念出来、抄下来、手打进输入框)
- 密码用户自设,至少 8 位,用 scrypt 加随机盐存储,不存明文
- 会话是**签名 cookie,服务端不存状态** —— 免费档休眠重启后不会把所有人登出
- **不收邮箱、不收手机号**,因此没有任何找回途径。号丢了账号就进不去了,
  但已发布的文章和证明不受影响
- 用户数据存在 `private/`(已 gitignore),**绝不进公开仓库**

默认不强制登录,和版本1 一致。要改成必须登录才能发布:环境变量 `EVERLOG_REQUIRE_LOGIN=1`。

# everlog

贴一篇文章,永久存进 Arweave,哈希锚进比特币区块。
任何人都能独立验证「谁在什么时候写的」—— **不需要相信这个网站,也不需要它还活着。**

---

## 这个仓库里是什么

```
data/articles/<id>/
  article.txt        文章的规范字节。这就是被丢进哈希函数的那串字节本身
  article.txt.ots    比特币时间戳证明(含完整 Merkle 路径 + 区块高度)
  receipt.txt(.ots)  把内容哈希和 Arweave 交易号绑在一起的回执
  meta.json          全部凭据
```

**`data/` 下的文件按二进制存放,git 不做任何换行转换**(见 `.gitattributes`)。
`article.txt` 是哈希原像,动一个字节所有证明作废 —— 而 Windows 上 git 默认会把
`\n` 换成 `\r\n`,那会让每一行多一个字节,哈希全废。这不是理论风险,是实测撞到过的。

## 自己验证一篇文章

```bash
# 1. 内容有没有被改过
sha256sum data/articles/<id>/article.txt
# 应与 meta.json 里的 sha256 一致

# 2. 这个哈希在比特币的哪个区块
pip install opentimestamps-client
ots info data/articles/<id>/article.txt.ots
# 末尾的 BitcoinBlockHeaderAttestation(N) 就是区块高度

# 3. 去任意区块浏览器查那个区块的时间
#    https://blockstream.info/block-height/N
```

不想装 Python 也行:网站上每篇文章都能下载一个 zip,里面附带一个
**单文件离线验证器**(`verify.html`),双击打开、断网可用,
会把从内容哈希一路合并到比特币 Merkle Root 的每一步算式显示出来。

## 时间是怎么被确定的

每篇文章拿到两条独立的时间线,每条都有两端:

| | 不早于 | 不晚于 |
|---|---|---|
| 比特币 | 文章头部嵌入的区块的 **MTP** | 文章哈希被锚定进的区块 |
| Arweave | 文章头部嵌入的区块 | 上传落进的区块 |

**下界**靠在文章里嵌入一个当时的区块哈希 —— 区块被挖出前没人能预测它,
所以文章必然写于其后。

**为什么用 MTP 而不是区块自己的时间戳:** 区块时间戳是矿工填的,
共识规则允许它超前真实时间最多两小时(实测撞到过超前 2 分钟的)。
拿它当下界会超额宣称。MTP(前 11 块时间戳的中位数)由共识保证落在过去,
松几十分钟,但站得住。

**顺序是精确的,钟点是模糊的。** 两篇文章谁先谁后,比区块高度即可,零模糊;
要和链外的日期比较,才被迫用上误差约一小时的钟点。

## 为什么每篇文章的证明也上了 Arweave

整套东西里唯一不可再生的就是 `.ots`。正文丢了能从 Arweave 捞回来,
比特币时间本来就在链上 —— 只有 `.ots` 如果只存在一块硬盘上,
坏了就是永久丢了(重新 stamp 只会拿到今天的时间戳,原来那个时刻再也证明不了)。

它只有几 KB,所以固化之后会再传一次 Arweave。
**everlog 关站、这个仓库消失、硬盘烧掉 —— 材料依然取得回来。**

## 这个仓库在整套东西里的位置

它是**第三条腿**,不是主力:

- **Arweave** 存正文和证明 —— 不依赖任何人
- **比特币** 定时间 —— 不依赖任何人
- **这个仓库** = 异地备份 + 一个外行看得懂的第三方时间记录

注意:**git 提交自带的日期是本机写的,可以随便伪造**
(`GIT_COMMITTER_DATE=1999-01-01 git commit` 完全合法),所以那个日期不是证据。
有价值的是 **GitHub 服务器记录的推送时刻** —— 公开仓库的推送会进入 GitHub 公开事件流,
被第三方持续归档,于是这个时间被一个和比特币、Arweave 都无关的地方抄走了一份。

## 格式

`everlog/1` 和 `everlog/2` 已冻结,永远保持可验证。
规范化规则一旦改动,历史文章的证明就全部作废 —— 要加东西只能出新版本号并存。

## 跑起来

```bash
npm install
node server.js          # 默认 8000 端口
node jobs/upgrade.js     # 手动跑一次证明升级(服务内已挂定时任务)
```

需要:Node 22+、Python 的 `opentimestamps-client`、一个 Arweave 钱包
(纯文本 96 KiB 以内走 Turbo 免费额度,钱包余额可以为 0)。
